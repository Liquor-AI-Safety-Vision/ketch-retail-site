# Ketch retail site and owner dashboard

The US retail / liquor-store pitch site for Ketch Enterprise and the Liquor Store owner
security dashboard, in one Vite app:

- the **landing page** and a **public, read-only dashboard demo** work without any backend;
- the **owner dashboard** (after `/#/login`) shows a store's real cameras, live view and the
  alerts the AI service raised, through the Go API in `../backend`.

| | |
|---|---|
| Stack | Vite 8 · React 19 · TypeScript · Tailwind v4 · Material UI · TanStack Query · hls.js · HashRouter |
| Served by | `deploy/` (Caddy on the same server as the API and the AI) |

> ⚠ **`ketchenterprise.net` (no "s") is this site.** `ketchenterprises.net` (with an "s") is a
> different site — the Vietnamese factory pitch — in a different repo. Until DNS is moved to
> the `deploy/` server, ketchenterprise.net is still the Cloudflare Pages deployment made from
> the old standalone repo (thinhEden/ketch-retail-site); nothing in this monorepo publishes to it.

## Run it

```bash
npm ci
cp .env.example .env
npm run dev        # http://localhost:5173; proxies /api to http://localhost:3000
```

The only browser variable is `VITE_API_BASE_URL` (normally `/api/v1`); secrets never go in
`VITE_*`. The landing page and the demo need nothing else. For the owner dashboard, run the Go
API (`../backend`, see `../backend/docs/environment.md`) against a database the AI service has
written to, and sign in at `/#/login`. Live view needs MediaMTX and the reverse proxy, i.e. the
`deploy/` setup.

Routes: `/#/` landing · `/#/login` · `/#/dashboard` overview · `/#/alerts` · `/#/cameras`.
HashRouter is deliberate: static hosting needs no rewrite rules.

```bash
npm run build          # writes public/_headers, then tsc -b && vite build -> dist/
npm run preview        # serve dist/
npm run lint
npm run test:security  # demo isolation and ROI checks (Node 22+)
npm run test:browser   # after `npm run preview -- --host 127.0.0.1`: CSP, demo, owner login (Chromium)
```

## Deploying

`deploy/build.sh` builds `dist/`; on the server, Caddy serves it beside `/api` (Go) and
`/live` (camera HLS). See `../deploy/README.md`.

## Public demo and owner access

- **View demo** opens the dashboard UI over `src/security-dashboard/lib/demoApi.ts`: static data
  in `lib/demoData.ts` and media in `public/demo-dashboard/`, both generated by
  `../ai/tools/build_frontend_demo.py` from store_test_01's manifest and this project's footage
  (see that script for where each clip comes from). No network calls, nothing writable.
- **Owner sign in** (`/#/login` or the account menu) is the only way to load real data. Only what
  the AI service wrote is shown there; nothing is generated in the browser.
- `/api/v1/auth/demo` returns 404; there is no server-held demo account.

## Security headers

`security/headers.js` defines the CSP and related headers; `npm run build` writes them to
`public/_headers`, and `deploy/render.py` applies the same set in Caddy (dropping HSTS and
`upgrade-insecure-requests` when the site runs on plain HTTP behind an SSH tunnel). Framing,
inline/eval JavaScript and plugins are blocked; media, images and API calls are same-origin
(`/api/v1/notification-review/...` for alert clips, `/live/...` for HLS). Inline styles stay
allowed for Material UI/Emotion and GSAP; hls.js runs without a worker so `blob:` scripts are
not needed.

## Product boundary

Dashboard alerts are review prompts, not automated verdicts. The owner remains responsible for
confirming normal alerts and handling emergency procedures. Keep source citations in
`src/lib/roi.ts` attached to landing-page benchmark numbers.

## Layout

```
src/
  main.tsx                    HashRouter; lazy-loads the dashboard application
  types.ts                    landing-page tier styles
  index.css                   Tailwind v4 design tokens
  lib/                        roi.ts (every constant carries its source), seo.ts, i18n, scrolling
  components/ui/              Button, Card, SectionShell, TierBadge
  pages/landing/              the landing page and its sections
  security-dashboard/         auth, shell, Overview/Alert/Camera pages, API client, demo API, theme
public/
  demo-dashboard/             demo camera loops and alert clips (generated, see above)
  landing/, live-cameras/, demo-source/, cctv/   landing-page and login imagery
```

Do not reuse them elsewhere. Resolving this is Huy's open item.
